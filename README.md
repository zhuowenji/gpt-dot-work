一个可自行部署的中文任务与问答入口：前台负责收集需求和继续对话，后台负责查看记录、回复、归类和保存摘要。前台保留原「任务聊天」页面的主要布局，并统一日夜主题。

这是独立、非官方项目，与 OpenAI 无隶属、合作或背书关系。它不是包含模型的「免费 dot 网页版」，不附送 OpenAI/ChatGPT 账号、订阅、模型或额度，也不保证使用与你的 dot 相同的模型。服务器、模型、账号和其他服务的可用性与费用由相应提供方决定。

**目前能够保存问题、记录和实际回复；真实 dot 执行连接尚未完成接入验证。** 收到问题、保存成功和排队状态，都不代表 dot 已读到或正在执行。网页不会编造在线员工、模型回复或已完成结果。

## 入口与使用方式

- `/`：公开任务聊天入口。访客不用注册或登录就能发送文字问题。
- 页面底部登录/注册：可选账号，只有账号和密码两项。账号唯一，普通账号密码至少 6 个字符，不要求大小写、符号等组合。登录后可跨设备继续自己的记录。
- `/admin/`：简单的记录、摘要与分类页面。后台仅管理员经独立认证后可用，用于处理访客问题和整理记录。普通用户仅使用前台及其自己的对话历史。后台没有新任务发布入口，新的问题和需求从前台添加。
- `/demo/`：保留的只读选品结果页，只展示明确公开、已核验的最小结果字段。没有真实公开结果时显示空状态。

匿名访客由随机浏览器 Cookie 区分，**不是按 IP 认人**。清除 Cookie 或换浏览器/设备会失去匿名记录的访问凭据；在当前浏览器注册或登录，可以把该浏览器有权访问的匿名记录关联到账号。登录不会凭 IP 找回其他人的记录。

普通账号不是管理员，也不能通过用户名、聊天内容、浏览器字段或接口参数获得所有者身份。所有者和访客的权限由服务器验证。

## 当前功能与限制

- SQLite 持久化对话、文字、回复、摘要、分类和幂等回执。
- 访客、不同普通账号和所有者之间的数据隔离；私有内容不会成为公开列表。
- 可选注册、登录、退出；密码只保存加盐 scrypt hash，登录限速、Cookie 会话和 CSRF/Origin 检查。
- 所有者可以在记录页实际回复，回复会出现在对应的原始对话中。
- 摘要和分类来自明确保存的整理结果；用户记忆支持版本、来源、纠错和失效。模块已发布，真实 AI 采用记忆的链路尚未验收，也不会自动把每条消息当作事实。
- 上传附件暂未开放。原页面的附件控件会说明这一限制，不会偷偷上传文件。
- 没有已接通的 AI 执行器，没有无凭证 Agent 注册/领取接口；访客问题绝不是任意操作的授权。
- MCP/OAuth/事件连接即使有候选代码，也只有在完成明确授权、安装连接和端到端测试后才能称为可用。
- 没有邮箱找回密码、MFA、经过验证的生产灾难恢复或完整渗透测试。普通账号的最低密码长度不是强密码保障，不建议存放高敏感信息。

旧的私有工作空间和选品数据保留在服务器中。历史执行队列 API 与新的问答记录分开，新的聊天消息不会自动变成可执行任务。旧工作空间的创建/发布界面不再作为 `/admin/` 入口。

## 本地检查与预览

需要 Node.js 24+；使用 Node 原生 HTTP、crypto 和 SQLite，无第三方 npm 运行依赖。

```sh
npm run check
npm --prefix backend run check
npm run build
npm run dev
```

`npm run dev` 只是本机视觉预览，不提供持久问答 API；页面会如实显示服务不可用。运行完整流程需要下述服务器配置和 `npm start`。构建结果含公开前台、简单管理页与只读结果页，不会自动发布。

`dist/preview.html` 保留旧工作空间的离线演示，仅用于历史布局参考，含虚构 localStorage 数据，不是在线管理入口，也不应存放真实敏感信息。

## 部署准备

先阅读 [部署说明](docs/DEPLOYMENT.md)、[后台说明](backend/README.md) 和 [问答记录模块](docs/CHAT_INTAKE.md)。

1. 选择专属运行目录和仓库外的 SQLite 数据目录，确认现有反向代理、运行用户、端口和备份方式。
2. 在可信终端使用现有密码 hash 工具设置独立所有者认证，把配置放到仓库外受保护文件。不要把密码、hash 或令牌写入前端、Git、聊天、命令行参数或日志。
3. 设置与最终访问地址完全一致的 `WORKSPACE_PUBLIC_ORIGIN`。生产环境需要 HTTPS，应用只监听本机回环端口。
4. 保持 `WORKSPACE_RUNTIME=disabled`。构建和测试通过后，通过已有发布机制启动服务。
5. 实际验证访客提问、注册/登录、匿名历史关联、两个账号隔离、所有者回复、退出、移动端和 HTTPS Cookie。部署成功不能替代这些检查。

```sh
npm run build
# 由现有运行机制注入认证、origin 和数据库配置之后：
npm start
```

如果已有 Git 自动部署脚本，可将 `sh deploy/prepare-release.sh` 用作检查与构建步骤。该脚本不会自行拉取、安装、改代理、重启服务或建立第二套调度。域名和已有部署机制以实际确认的配置为准。

## 数据与隐私

- 匿名会话和账号只能读取其有权访问的对话；所有者可为回复与整理查看提交到本服务的内容。
- IP 可用于防滥用限速，不能用来领取、迁移或合并对话。
- 数据库、会话、密码 hash、备份和日志必须在 Git 与静态目录之外；`.gitignore` 不是访问控制。
- 需要合理的数据保留、容量上限和备份流程。清除浏览器 Cookie 不等于删除服务器记录。
- 备份含私有内容与认证数据，应保护并在恢复后撤销旧会话。
- 已公开的选品结果只包含白名单字段，私人证据、内部备注、作者扩展信息和账号资料不会随之公开。
- 不包含第三方字体、图片、遥测或 CDN；使用系统字体和基础 SVG。
